# Signup concept

We do NOT want students manually choosing their own Student ID and password.

Instead, the backend will generate the student's credentials.

The student enters their **email address**.

The frontend sends the email to the backend.

The backend then:

1. Checks the email.
2. Creates/associates an account with that email.
3. Generates a Student ID.
4. Generates a password.
5. Returns the generated Student ID and password to the frontend.

The frontend then displays those credentials to the student.

The student must be clearly told to save their credentials somewhere safe.

# API REQUEST

When the student clicks:

**Generate My Credentials**

send a POST request to:

```text
<BACKEND_URL>/api/signup
```

The backend URL should be stored in a configurable environment variable rather than hardcoded throughout the application.

For example, use a Next.js public environment variable such as:

```text
NEXT_PUBLIC_API_URL
```

Then construct the endpoint from it:

```text
${NEXT_PUBLIC_API_URL}/api/signup
```

---

# Request method

The request must be:

```http
POST
```

with:

```http
Content-Type: application/json
```

The frontend sends the student's email as JSON.

Example:

```json
{
  "email": "student@example.com"
}
```

Example JavaScript:

```javascript
const response = await fetch(`${process.env.NEXT_PUBLIC_API_URL}/api/signup`, {
  method: "POST",
  headers: {
    "Content-Type": "application/json"
  },
  body: JSON.stringify({
    email: email
  })
});
```

If the project uses a different Next.js client-side environment variable pattern, follow the correct Next.js convention.

IMPORTANT:

The frontend must NOT generate the Student ID.

The frontend must NOT generate the password.

The backend generates both.

with JSON containing the generated Student ID and password.
